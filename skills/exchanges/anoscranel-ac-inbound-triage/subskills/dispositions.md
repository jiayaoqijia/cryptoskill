# Dispositions

## Standard

- **Allen, _Getting Things Done_ (2001)**: the inbox decision is do it, delegate it, or defer it; anything under a small threshold of time should be done now rather than tracked. <https://gettingthingsdone.com/>
- **Rumelt, _Good Strategy Bad Strategy_ (2011)**: a choice that does not name what it will not do is not a choice; dropping work must be explicit, not accidental. <https://www.penguinrandomhouse.com/books/205843/good-strategy-bad-strategy-by-richard-rumelt/>
- **Scrum Guide (2020)**: a timebox caps an activity; it forces an end so the next decision can happen. <https://scrumguides.org/scrum-guide.html>

## Decision rules

1. If the item is done in under a set timebox and only I can do it, act now.
2. If it matters but is not time-critical, schedule it; give it a date, not "later".
3. If someone else can do it and needs no hand-holding, delegate it.
4. If nothing breaks when it is not done, drop it and record the drop.
5. If an "act now" item keeps growing past its timebox, stop and re-triage; it was not an act-now item.

## Procedure

1. Read the item and name the single outcome it asks for.
2. Apply the four tests in order: timebox, owner, deadline, and breakage.
3. Act now: start immediately and stop at the timebox; if unfinished, re-triage.
4. Schedule: pick a date and a slot; put it on the calendar, not a someday list.
5. Delegate the item: hand over the outcome, the deadline, the decision rights, and the context; keep nothing that is the other person's job.
6. Drop: write one line saying what was dropped and why; file it where drops are reviewed.
7. Record the disposition beside the item so the next person does not re-triage it.

## Anti-patterns

- **Everything is act-now.** The timebox is ignored and the queue never drains. Fix: cap act-now by the timebox and re-triage what exceeds it.
- **Schedule without a date.** "Later" is a queue, not a schedule. Fix: name the date.
- **Delegation as a hand-off of the task only.** Without outcome, deadline, and rights, the work comes back. Fix: hand over all four.
- **Silent drop.** An item is ignored until it disappears; nobody knows it was dropped or why. Fix: record every drop.
- **Re-triaging the same item.** A disposition already assigned gets scored again. Fix: the disposition is recorded and reused.

## Done checklist

- [ ] The single outcome is named for each item.
- [ ] Act-now items ran inside their timebox or were re-triaged.
- [ ] Scheduled items have a date and a slot.
- [ ] Delegated items carry outcome, deadline, decision rights, and context.
- [ ] Every drop is recorded with a one-line reason.
- [ ] The disposition is written beside the item.
