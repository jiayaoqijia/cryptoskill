# Verify seed phrase entropy

A phrase can be the right length and still be worthless if the randomness behind it was weak. This skill confirms the generator, the entropy budget, and the checksum, and rejects phrases whose source cannot be named.

## Procedure

1. Name the entropy source. Acceptable: an OS CSPRNG (`/dev/urandom`, `getrandom(2)`) or a hardware TRNG. Unacceptable: time-based seeds, `Math.random`, or an unidentified website.
2. Confirm the word count matches the claimed strength. BIP-39 word count is fully determined: 12→128 bits, 18→192, 24→256. Any 15-word phrase is not generated by a conforming tool and is suspect.
3. Validate the checksum offline:
   ```python
   from mnemonic import Mnemonic
   m = Mnemonic("english")
   phrase = open("candidate.mn").read().strip()
   assert len(phrase.split()) in (12, 15, 18, 21, 24)
   assert m.check(phrase), "checksum invalid"
   print("checksum ok, entropy bits:", 32 * len(phrase.split()) * 11 // 33)
   ```
4. Confirm the wordlist is the canonical 2048-word English list, not a lookalike:
   `python3 -c "from mnemonic import Mnemonic; print(len(Mnemonic('english').wordlist))"` → must print `2048`.
5. Cross-generate: run two independent generators (e.g. the `mnemonic` library and a hardware wallet) and confirm neither produces a phrase you have seen documented as a known-compromised vector. Reject any phrase whose first 4 words appear in public "vanity"/profanity-generation dumps.
6. Only after all checks pass, fund the wallet.

## Pitfalls

- A valid checksum does not imply good entropy; attacker-chosen phrases can carry a correct checksum. Checksum checks the typo, not the randomness.
- Twelve words from a strong CSPRNG are 128 bits and are fine; the danger is *weak* entropy, not short length.
- Regenerating until you "like" the address biases the sample and can strip entropy. Don't reject valid phrases for aesthetics.
- Copying a phrase from a tutorial or repo means it is public; treat any published phrase as already stolen.
