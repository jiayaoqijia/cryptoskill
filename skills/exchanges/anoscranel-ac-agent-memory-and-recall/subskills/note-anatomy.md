# Note anatomy

## Standard

A memory note is written twice: once to store it and once to find
it. The anatomy serves both passes. One fact per note keeps
contradictions addressable — you supersede a fact, not a paragraph
of intertwined facts. A title that names the fact in the words a
future query will use makes retrieval a title scan rather than a
full re-read. A date gives every claim a shelf life. Tags give
coverage maps something to count.

The failure mode is the diary entry: a well-written paragraph that
mixes what changed, why it changed, what it means, and what might
come next. Retrieval finds it; the reader must then do the
separation work the writer skipped. The atomic note pays its cost
up front, at write time, when the context is still loaded in the
writer's head.

Primary sources: <https://en.wikipedia.org/wiki/Zettelkasten> and <https://en.wikipedia.org/wiki/Personal_knowledge_base>.

## Decision rules

- One fact per note, stated in the first sentence.
- Title names the fact in the terms a future query would use.
- Date every note at writing; undated memory cannot age honestly.
- Tags name domains or themes, not moods; coverage is countable.
- Links between notes for context, not inline essays.
- A note that needs three sentences of preamble to state its fact is three notes.

## Procedure

1. State the fact in the first sentence; test whether it alone survives being read out of context.
2. Give the note a title a searcher would type.
3. Add the date and tags in the header block.
4. Link related notes rather than restating the relation each time it is mentioned.
5. Split any note that carries more than one fact.
6. Verify each note with an out-of-context read: does it still mean what it meant?

## Anti-patterns

- Diary entries mixing several facts in flowing prose.
- Clever titles that no future query would guess.
- Undated notes presented as current knowledge.
- Restating the same fact in five notes rather than one note and four links.
- Notes that need their author's session context to parse.

## Done checklist

- [ ] One fact per note, first sentence.
- [ ] Title phrased as a future query would phrase it.
- [ ] Date recorded at write time.
- [ ] Tags countable, domain-named.
- [ ] Links to related notes.
- [ ] Out-of-context read test passed.
