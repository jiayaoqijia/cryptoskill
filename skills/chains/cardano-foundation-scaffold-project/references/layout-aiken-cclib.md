# Layout: Aiken + cardano-client-lib (Stack 4)

Stack 4 targets a JVM team -- Java, Kotlin, or any other JVM language. Aiken on-chain emits a CIP-57 `plutus.json` blueprint; cardano-client-lib off-chain consumes it. The Java project uses Maven; Gradle is a reasonable substitution if your team prefers it (translate the `pom.xml` to a `build.gradle.kts` 1:1).

### Hello-world off-chain class -- `Blueprint.java`

```java
// src/main/java/org/acme/offchain/Blueprint.java
//
// Loads the CIP-57 plutus.json blueprint emitted by `aiken build` and returns
// typed wrappers for each named validator. Every cclib caller asks Blueprint
// for the script -- never re-derive the script hash by hand.

package org.acme.offchain;

import com.bloxbean.cardano.client.plutus.blueprint.PlutusBlueprintUtil;
import com.bloxbean.cardano.client.plutus.blueprint.model.PlutusVersion;
import com.bloxbean.cardano.client.plutus.spec.PlutusScript;
import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;

import java.nio.file.Files;
import java.nio.file.Path;

public final class Blueprint {

    public record Validator(PlutusScript script, String scriptHash) {}

    private final JsonNode root;

    public Blueprint(Path plutusJsonPath) throws Exception {
        var mapper = new ObjectMapper();
        this.root = mapper.readTree(Files.readString(plutusJsonPath));
    }

    public Validator getValidator(String title) {
        for (JsonNode v : root.get("validators")) {
            if (title.equals(v.get("title").asText())) {
                // Aiken's compiledCode is CBOR-wrapped once; cclib's script type
                // expects one more layer. This util adds it, so the script's hash
                // (and address) matches the blueprint's.
                var script = PlutusBlueprintUtil.getPlutusScriptFromCompiledCode(
                    v.get("compiledCode").asText(), PlutusVersion.v3);
                return new Validator(script, v.get("hash").asText());
            }
        }
        throw new IllegalArgumentException(
            "Validator '" + title + "' not found in plutus.json. Did you run 'aiken build'?"
        );
    }
}
```

### Hello-world off-chain class -- `ChainClient.java`

```java
// src/main/java/org/acme/offchain/ChainClient.java
//
// Builds a BackendService. Devnet uses Yaci Store's Blockfrost-compatible API;
// preview/preprod/mainnet uses real Blockfrost. Mainnet requires explicit opt-in.

package org.acme.offchain;

import com.bloxbean.cardano.client.backend.api.BackendService;
import com.bloxbean.cardano.client.backend.blockfrost.service.BFBackendService;
import com.bloxbean.cardano.client.common.model.Networks;
import com.bloxbean.cardano.client.common.model.Network;

public final class ChainClient {

    public record ConfiguredBackend(BackendService backend, Network network) {}

    public static ConfiguredBackend fromEnv() {
        String network = System.getenv().getOrDefault("CARDANO_NETWORK", "devnet");

        if ("devnet".equals(network)) {
            String url = System.getenv().getOrDefault("YACI_STORE_URL", "http://localhost:8080");
            // Yaci Store exposes a Blockfrost-compatible API on /api/v1.
            var backend = new BFBackendService(url + "/api/v1/", "devnet");
            return new ConfiguredBackend(backend, Networks.testnet());
        }

        String projectId = System.getenv("BLOCKFROST_PROJECT_ID");
        if (projectId == null || projectId.isBlank()) {
            throw new IllegalStateException(
                "BLOCKFROST_PROJECT_ID required when CARDANO_NETWORK is not devnet"
            );
        }
        return switch (network) {
            case "mainnet" -> new ConfiguredBackend(
                new BFBackendService(
                    "https://cardano-mainnet.blockfrost.io/api/v0/", projectId),
                Networks.mainnet());
            case "preview" -> new ConfiguredBackend(
                new BFBackendService(
                    "https://cardano-preview.blockfrost.io/api/v0/", projectId),
                Networks.preview());
            case "preprod" -> new ConfiguredBackend(
                new BFBackendService(
                    "https://cardano-preprod.blockfrost.io/api/v0/", projectId),
                Networks.preprod());
            default -> throw new IllegalArgumentException("Unknown network: " + network);
        };
    }
}
```

### Hello-world off-chain class -- `Lock.java`

```java
// src/main/java/org/acme/offchain/hello/Lock.java
//
// Locks 5 ADA at the hello validator. Run with:
//   mvn -q exec:java -Dexec.mainClass=org.acme.offchain.hello.Lock

package org.acme.offchain.hello;

import com.bloxbean.cardano.client.account.Account;
import com.bloxbean.cardano.client.address.AddressProvider;
import com.bloxbean.cardano.client.api.model.Amount;
import com.bloxbean.cardano.client.function.helper.SignerProviders;
import com.bloxbean.cardano.client.plutus.spec.BytesPlutusData;
import com.bloxbean.cardano.client.plutus.spec.ConstrPlutusData;
import com.bloxbean.cardano.client.plutus.spec.PlutusData;
import com.bloxbean.cardano.client.quicktx.QuickTxBuilder;
import com.bloxbean.cardano.client.quicktx.Tx;

import org.acme.offchain.Blueprint;
import org.acme.offchain.ChainClient;

import java.math.BigInteger;
import java.nio.file.Path;

public final class Lock {

    public static void main(String[] args) throws Exception {
        var configured = ChainClient.fromEnv();
        var blueprintPath = Path.of(System.getenv().getOrDefault(
            "BLUEPRINT_PATH", "../onchain/plutus.json"));
        var blueprint = new Blueprint(blueprintPath);
        var hello = blueprint.getValidator("hello.hello.spend");

        // Dev wallet from mnemonic; treat as dev-only.
        var mnemonic = System.getenv("DEV_WALLET_MNEMONIC");
        if (mnemonic == null) throw new IllegalStateException("DEV_WALLET_MNEMONIC not set");
        var account = new Account(configured.network(), mnemonic);

        // Script address.
        var scriptAddr = AddressProvider.getEntAddress(hello.script(), configured.network());

        // Build, sign, submit using QuickTxBuilder.
        var quickTxBuilder = new QuickTxBuilder(configured.backend());
        // Inline datum: HelloDatum { owner: <payment key hash bytes> }.
        // Constructor 0, one ByteArray field — field order follows the Aiken type.
        var ownerVkh = account.getBaseAddress().getPaymentCredentialHash().orElseThrow();
        PlutusData datum = ConstrPlutusData.of(0, BytesPlutusData.of(ownerVkh));

        var tx = new Tx()
            .payToContract(scriptAddr.toBech32(), Amount.lovelace(BigInteger.valueOf(5_000_000)), datum)
            .from(account.baseAddress());

        var result = quickTxBuilder
            .compose(tx)
            .withSigner(SignerProviders.signerFrom(account))
            .completeAndWait();

        System.out.println("Locked. Tx hash: " + result.getValue());
    }
}
```

`ConstrPlutusData.of(constructorIndex, fields...)` maps onto an Aiken constructor, and field order is the declaration order in the Aiken type. For datums larger than a field or two, generate the Java types from the CIP-57 blueprint with the annotation processor instead of hand-encoding — see `../../docs/sources/cardano-client-lib/annotations/plutus-blueprint-code-generation.mdx`.

A matching `Redeem.java` queries the script address through the backend service, picks the locked UTxO, and spends it with `ScriptTx().collectFrom(List.of(utxo), redeemer).attachSpendingValidator(script)` — the validator is attached inline, so nothing needs to be published first, and QuickTx selects collateral automatically. The complete pattern, including the `withSigner` vs `withRequiredSigners` distinction, is in `../../skills/build-transaction/references/cclib-quicktx.md`; a full runnable program is at `../../docs/sources/cardano-use-case-templates/vesting/offchain/ccl-java/Vesting.java`.

## Network config patterns

Three places to flip when switching networks:

1. `CARDANO_NETWORK` in `.env` (devnet | preview | preprod | mainnet). Default to a testnet; never mainnet.
2. `ChainClient.java` (already shown above) builds a `BFBackendService` with the matching Blockfrost URL and a `Networks.testnet() / preview() / preprod() / mainnet()` selector.
3. If you scaffold a sibling frontend (see below), its `.env.local` mirrors `CARDANO_NETWORK` and uses its own Blockfrost project ID.

Each non-devnet network needs its own Blockfrost project ID from https://blockfrost.io (distinct prefixes: `preview...`, `preprod...`, `mainnet...`). Faucets for preview and preprod live at https://docs.cardano.org/cardano-testnets/tools/faucet. On devnet, fund an address with `topup <address> <ada>` at the yaci-cli prompt.

## Frontend (optional sibling, default ON in the scaffold)

A JVM backend cannot run in the browser. When the developer opts in to a frontend, scaffold a separate Next.js App Router app — independent of the Java backend — that talks directly to Blockfrost from the user's browser. The frontend reads the same `onchain/plutus.json` (committed alongside the backend) and does its own client-side tx building.

```
acme-dapp/
├── onchain/
│   └── plutus.json                   # shared between backend and frontend
├── offchain/                         # Java/Kotlin backend
│   └── ...
└── frontend/                         # NEW, separate Next.js app
    ├── package.json
    ├── tsconfig.json
    ├── next.config.mjs
    ├── app/
    │   ├── layout.tsx
    │   ├── page.tsx
    │   └── lib/
    │       ├── blueprint.ts          # imports ../../../onchain/plutus.json
    │       └── tx.ts                 # Mesh or Evolution tx-building helpers
    └── .env.local.example            # NEXT_PUBLIC_NETWORK; project ID stays server-side
```

The frontend uses Mesh or Evolution for CIP-30 and tx building. See `references/layout-aiken-mesh.md` or `references/layout-aiken-evolution.md` for the frontend section in each variant.

The JVM backend stays as-is. Use it for batch jobs, indexing, data pipelines, Spring Boot endpoints, or other server-side workloads. User-facing transactions are built and signed by the browser via CIP-30.

Hand off to `connect-wallet` for the CIP-30 wallet integration content.

## Next steps

2. **Start Yaci DevKit** -- hand off to `setup-devnet`. Copy the dev wallet mnemonic into `.env`.
3. **Run `mvn install` in `offchain/`** -- pulls cardano-client-lib and dependencies.
4. **Run `mvn -q exec:java -Dexec.mainClass=org.acme.offchain.hello.Lock`** -- exercises the on-chain / off-chain bridge.
5. **Write real validator logic** -- hand off to `write-validator`.
6. **Write real transactions** -- hand off to `build-transaction`.

Spring Boot or Quarkus integration: cclib has Spring Boot starters. If the project is part of an existing Spring service, wire the `BackendService` and `Account` as beans, and read network configuration from `application.yml` instead of bare env vars.
