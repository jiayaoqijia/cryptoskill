# Question Craft

## Standard

- **Fitzpatrick, _The Mom Test_ (2013)**: talk about the person's life, not your idea; ask about past behaviour, because hypotheticals and compliments carry no data. <https://momtestbook.com/>
- **Brooks & John, "The Surprising Power of Questions"** (HBR, 2018): open questions start the exchange; follow-up probes produce the content. <https://hbr.org/2018/05/the-surprising-power-of-questions> ⚠️ paywalled.
- **Socratic method** (Stanford Encyclopedia of Philosophy, "Socrates"): a question is an instrument of examination, not a trap or a verdict. <https://plato.stanford.edu/entries/socrates/>
- ⚠️ Practitioner convention: the condition question — "what would have to be true for this to hold?" — turns an assertion into testable conditions.

## Decision rules

1. If a question invites yes, no, or a prediction about the speaker's own future, rewrite it about the past.
2. If the answer is an opinion, ask for the last concrete instance.
3. If you are speaking more than a third of the time, stop talking and ask what happened next.
4. If a claim arrives polished, ask what would have to be true for it to hold, then test one condition.
5. If you already know the answer you want, the question leads; use it only as a stated test, never as discovery.
6. If an answer ends, wait three seconds before speaking; the second sentence carries the substance.
7. If you drafted five questions, keep two and hold the rest as follow-ups.

## Procedure

1. Write each question on one line in plain words. Read it aloud.
2. Convert future to past: "would you use this" becomes "when did you last hit this problem, and what did you do?"
3. Prefer "what" and "how" over "why"; "why" reads as an accusation and draws justification, while "what made this seem right" invites the account.
4. Follow the specifics: "what happened next", "how much did that cost", "what did you try first".
5. Use the condition question once per major claim: "what would have to be true for this to work?" Write down each condition as it is spoken.
6. Stay silent after an answer. Count three beats. Most people fill the gap with the real reason.
7. Close each thread by paraphrasing back what you heard and asking if it is right.

## Anti-patterns

- **The hypothetical.** "Would you use a product like this?" produces politeness, not data. Fix: ask about the last time the problem occurred.
- **The leading question.** "Don't you think this is risky?" plants its answer. Fix: open form, then listen for the risk unprompted.
- **Stacked questions.** Two questions at once get one answer, usually to the easier one. Fix: one at a time.
- **Why as a weapon.** "Why would you do that?" demands defence. Fix: "what made this seem right at the time?"
- **Filling silence.** Talking over the pause discards the best answer. Fix: wait.
- **Solution masquerading as a question.** "What if you just cached it?" is pitching. Fix: park solutions until the examination closes.

## Done checklist

- [ ] Every question asks about the past or a concrete condition.
- [ ] No question embeds the answer the asker wants.
- [ ] Follow-up probes written before the session.
- [ ] Silence used at least once per thread.
- [ ] Each thread closed with a confirmed paraphrase.
