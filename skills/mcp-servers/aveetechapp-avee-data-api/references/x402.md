# Paying past the keyless limit with x402

x402 lets a client pay for one HTTP call in USDC with no account. On avee it is **only** the way
past a spent keyless budget: every route stays free within the budget.

## Before anything else

- Use it only when the user has explicitly supplied a payer (a wallet or an x402 client library they
  control) and agreed to pay. Never sign or pay on your own.
- It is off until enabled on the host. Check `GET /.well-known/x402`: a `404`, or an empty list,
  means it is off, and a `429` is simply "wait `Retry-After`".
- A caller with a valid API key is never offered a price.

## The exchange, when enabled

| Your request | The answer when the budget is spent |
|---|---|
| no opt-in | `429` with `Retry-After`, plus a `PAYMENT-REQUIRED` header (base64 x402 v2 requirements) you may ignore |
| `Accept-Payment: x402` | `402` with the requirements in `PAYMENT-REQUIRED` and in the JSON body; `Retry-After` stays |
| `PAYMENT-SIGNATURE: <base64 payload>` | the budget is skipped; verified, served, and settled only on a `2xx`; receipt in `PAYMENT-RESPONSE` |

Steps for a client with a payer:

1. Send the request with `Accept-Payment: x402`.
2. On `402`, read the requirements (header first, body second) and pick one `accepts` entry
   (scheme `exact`, a network, the USDC amount, `payTo`).
3. Sign it with the payer and repeat the same request with `PAYMENT-SIGNATURE`.
4. Reuse one `payment-identifier` across your own retries of the same call: a replay returns the
   stored answer without a second charge.

A `4xx` or `5xx` answer is never settled. A malformed request is `400` and is never priced. The price
follows the route's CU; `GET /.well-known/x402` lists each payable route and its price. The verdict and
proof routes are never priced.
