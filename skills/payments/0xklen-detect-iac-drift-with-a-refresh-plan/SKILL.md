# Detect IaC drift with a refresh plan

Drift is any live change not in code: a console edit, a manual scale-up, a deleted security-group rule. A refresh-only plan shows it without proposing unrelated changes.

## Procedure

1. Run a plan that refreshes state and proposes no config changes, on a schedule (nightly):
       terraform plan -refresh-only -out=drift.tfplan
       terraform show -json drift.tfplan | jq '.resource_changes[]? | select(.change.actions != ["no-op"])'
2. Alert on any resource whose refreshed attributes differ from state. `-refresh-only` lists updates but never plans to change infrastructure, so it is safe against production.
3. Confirm the drift is real: `terraform plan -refresh-only -json` distinguishes a provider-normalised value (harmless) from a resource that truly changed.
4. If the live value is correct, codify it: update the `.tf` and `terraform apply -refresh-only` to accept the new state. Do not blanket-apply code over reality.
5. If the live value is wrong, plan the revert with `terraform plan -target=<addr>`, read the diff, then apply that scoped plan.
6. Run the check in CI and open a ticket on non-empty drift; a dashboard nobody reads is not a control.
7. Ignore attributes the provider manages out of band (autogenerated tags, computed IDs) with `lifecycle { ignore_changes = [...] }` so the alert stays signal.
8. Store the drift plan as a CI artefact with the commit SHA for audit.

## Pitfalls

- `terraform apply` to fix drift without reading the plan can revert a deliberate hotfix made under pressure.
- Treating every refreshed change as drift: computed fields and normalised casing produce false positives that train people to ignore the alert.
- Running a full plan (not `-refresh-only`) that also proposes config changes, making drift indistinguishable from pending work.
- A drift check that only runs on merge, so console changes accumulate unnoticed for weeks.
- Ignoring `-target` scope when reverting and reverting more than intended.

- Running the drift check with a provider other than the pinned one, so refresh rewrites attributes and reports phantom drift.
- A refresh over one very large state that times out; scope the check per stack, not one monolithic file.

## Verification

    terraform plan -refresh-only -detailed-exitcode; echo "exit=$?"
    # 0 = no drift, 2 = drift present

Report: the schedule, the exit code observed, the drifted resource addresses, and whether each was codified or reverted.
