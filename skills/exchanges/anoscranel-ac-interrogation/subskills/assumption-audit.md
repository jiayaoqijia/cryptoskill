# Assumption Audit

## Standard

- **Lovallo & Kahneman, "Delusions of Success"** (HBR, 2003): plans lean on the inside view — assumptions drawn from the plan itself; testing them means stepping to the outside view of similar cases. <https://hbr.org/2003/07/delusions-of-success-how-optimism-undermines-executives-decisions> ⚠️ paywalled.
- **Popper on falsification** (Stanford Encyclopedia of Philosophy, "Karl Popper"): a claim earns its status by stating what would refute it; an assumption that cannot fail is a belief in disguise. <https://plato.stanford.edu/entries/popper/>
- **Galef, _The Scout Mindset_ (2021)**: treat beliefs as a map to correct, not a position to defend. ⚠️ cited without URL.
- ⚠️ House convention: confidence labels — high (direct evidence in hand), medium (indirect evidence), low (reasoning only), unverified (nobody checked). The label cites its evidence, not a feeling.

## Decision rules

1. If an assumption is never spoken aloud, it cannot be tested; write it down the moment it surfaces.
2. If its falsity would not change the plan, it is incidental; park it.
3. If its falsity collapses a named part of the plan, it is load-bearing and gets a cheap test or an explicit risk entry.
4. If a test costs more than the decision is worth, use a proxy check, or flag the assumption unverified and move on.
5. If the author says "everyone knows", run the premise check: verified by whom, when, against what?
6. If a confidence label has no reason attached, downgrade it to unverified.
7. Rank by load-bearing times uncertainty; test the top two, not the whole list.

## Procedure

1. Re-read the plan and mark every statement presented as settled fact.
2. Convert each to an assumption sentence: "we are assuming that X is true."
3. Run the premise check on each: if X were false, what breaks? Name the specific part.
4. Sort the list: load-bearing (collapse risk) versus incidental (cosmetic or easily patched).
5. For each load-bearing assumption, write the cheapest test that could show it false: one lookup, one data pull, one question to a user, a two-day trial.
6. Label confidence before testing: high, medium, low, or unverified.
7. Run the cheap tests now if the session allows; otherwise assign each a named owner.
8. Write the ledger: assumption, load-bearing flag, test, result or owner, confidence after the test.

## Anti-patterns

- **The endless list.** Forty assumptions exhaust the session and test nothing. Fix: stop at the load-bearing set.
- **Testing the incidental first.** Easy checks crowd out the ones that matter. Fix: rank by collapse risk before testing.
- **Vibes confidence.** "I am 90% sure" with no reason. Fix: every label cites its evidence.
- **Constraints dressed as assumptions.** Budget limits are imposed, not assumed. Fix: separate chosen premises from fixed constraints; only chosen ones can be revised.
- **"Everyone knows".** Fix: name the verifier, the date, the source — or mark it unverified.

## Done checklist

- [ ] Every settled statement converted to an assumption sentence.
- [ ] Each assumption marked load-bearing or incidental.
- [ ] Premise check run: what collapses if it is false.
- [ ] A cheap test named for each load-bearing assumption.
- [ ] Ledger written with confidence labels and owners.
