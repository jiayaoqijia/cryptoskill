## Purpose

Concept web-specific motion and microinteraction behaviors aligned to UX goals and brand tone.

## Use when

- A web interface needs interaction/motion concepts tied to usability and brand feel.
- The task is web UX motion concepting, not video storyboard production.

## Required inputs

- Target pages/components and interaction goals [client-provided].
- Brand context from context/BRAND-CONTEXT.template.md and context/CLIENT-CONTEXT.template.md.
- Performance/accessibility constraints and technical limits.

## Safety/authority

- No fabricated implementation feasibility claims; mark assumptions clearly.
- No direct code deployment or runtime changes.
- Provide concept guidance and acceptance criteria only.

## Workflow

1. Map user actions and feedback moments that benefit from motion.
2. Define microinteraction behaviors, timing intent, and reduced-motion variants.
3. Document UX rationale and potential risks (performance, distraction, accessibility).
4. Provide concept package for design/dev handoff.

## Output format
```

- Motion concept summary
- Interaction map (trigger | behavior | intent)
- Accessibility/performance guardrails
- Handoff notes and open questions
```

## Quality checks

- Each motion concept has functional UX purpose, not decoration-only.
- Reduced-motion/accessibility considerations are explicitly included.
