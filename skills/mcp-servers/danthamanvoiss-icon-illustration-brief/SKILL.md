## Purpose

Draft icon/illustration requirements brief for style consistency, usage cases, and production constraints.

## Use when

- Product or marketing teams need new icon/illustration sets defined before design execution.
- You need style/system requirements rather than immediate artwork generation.

## Required inputs

- Use cases and target contexts [client-provided].
- Brand context via context/BRAND-CONTEXT.template.md and context/CLIENT-CONTEXT.template.md.
- Technical/output constraints (sizes, formats, accessibility).

## Safety/authority

- No invented licensing, attribution, or usage rights assumptions.
- No final asset generation claim; brief-only draft output.
- Mark unknown format or accessibility requirements for confirmation.

## Workflow

1. Define purpose, audience readability needs, and semantic categories.
2. Set style rules (stroke/fill, corner radius, perspective, color behavior).
3. Specify deliverable package and QA checks.
4. List unresolved constraints and approvals.

## Output format
```

- Icon/illustration brief summary
- Style rules matrix
- Deliverable and export requirements
- Open questions and approval gates
```

## Quality checks

- Style rules are explicit enough to prevent cross-asset drift.
- Requirements include accessibility and format constraints.
