# Close and Stop

## Standard

- **Duke, _Quit_ (2022)**: define stopping conditions before starting; a plan without exit criteria runs on inertia. ⚠️ cited without URL.
- **Tetlock & Gardner, _Superforecasting_ (2015)**: past a point, new information stops moving the probability; that point is where analysis ends. ⚠️ cited without URL.
- **Klein, "Performing a Project Premortem"** (HBR, 2007): the pre-mortem yields early warning signals; those become the kill criteria a close note records. <https://hbr.org/2007/09/performing-a-project-premortem> ⚠️ paywalled.
- ⚠️ House convention: the anti-loop cap — two rounds over the same ground is the limit; a third pass needs a new named question.

## Decision rules

1. If new information no longer changes the decision, stop; that is criterion one.
2. If a question has been asked twice with the same answer, do not re-ask; record it or move on.
3. If the session has run two full rounds over the same ground, close.
4. If fatigue shows — answers shortening, attention drifting — close early; a tired session manufactures false certainty.
5. If the decision is ready — remaining uncertainty sits inside the cost of waiting — stop; commitment supplies the rest.
6. If the plan dies under questioning, close with a kill recommendation and kill criteria; killing early is a result, not a failure.
7. If the owner cannot commit, close as deferred with a named date and owner; undated deferrals decay into zombie plans.

## Procedure

1. At the start, write the stop criteria: what would make this session done, dead, or deferred.
2. Open each round with the readiness check: would new information change the choice? If no, stop.
3. Run the repetition check: list questions already answered; strike repeats from the queue.
4. Enforce the cap. Two rounds over the same ground maximum; a third needs a new named question and a reason it can change the outcome.
5. Close with the four-part record: revised plan (what changes), unresolved items (owner and date each), assumption ledger (assumption, confidence, test result), kill criteria (observable signals that mean stop).
6. Read the record back to the owner. The owner commits, kills, or defers with a date.
7. Share the record; the next review starts from the file, not memory.

## Anti-patterns

- **Interrogation as procrastination.** More questions postpone a commitment the author fears. Fix: name the commitment date and work backwards.
- **The loop.** Answered questions re-asked in new words. Fix: the repetition check plus the two-round cap.
- **Closing without a record.** The session ends and nothing survives. Fix: the four-part close note, written before anyone leaves.
- **Zombie plan.** Deferred forever, owned by nobody. Fix: date and name every deferral.
- **Kill criteria never set.** The plan cannot fail because failure was never defined. Fix: every close ends with the stop signals.

## Done checklist

- [ ] Stop criteria written before the session started.
- [ ] Repetition check run; no question asked twice.
- [ ] Two-round cap respected, or the exception named.
- [ ] Close note holds revised plan, unresolved items, assumption ledger, kill criteria.
- [ ] Owner commits, kills, or defers with a date.
