# Koinju REST API quick reference

Base URL: `https://api.koinju.io`

## Public endpoints (no auth) — use for ALL market / product / instrument discovery

**Rule**: any "what markets / products / instruments exist?" question goes through these endpoints, not SQL. No API key, no ClickHouse setup, just `curl` + `jq`. This applies even when the rest of the user's workflow is SQL-heavy.

| Endpoint | Returns |
|---|---|
| `/market/spot` | All spot pairs across all exchanges |
| `/market/future` | All perpetuals + dated futures |
| `/market/option/active` | Currently-listed options |
| `/market/option/all` | All options (incl. expired) |

Schema discovery — peek at one row first to confirm field names (live schema is the source of truth):

```bash
curl -s 'https://api.koinju.io/market/spot' | jq '.[0]'
```

Actual fields (verified against live API):

| Endpoint | Fields |
|---|---|
| `/market/spot` | `exchange`, `market_symbol`, `base_asset`, `quote_asset`, `exchange_specific_symbol` |
| `/market/future` | `exchange`, `market_symbol`, `underlying_asset`, `quote_asset`, `settling_asset`, `denomination_asset`, `expiration`, `contract_size`, `contract_type`, `future_type`, `exchange_specific_symbol` |
| `/market/option/active` | `exchange`, `market_symbol`, `underlying_asset`, `quote_asset`, `settling_asset`, `expiration`, `strike`, `contract_size`, `contract_type`, `option_type` (`CALL`/`PUT`), `exchange_specific_symbol` |

Note: spot uses `base_asset` / `quote_asset`; futures and options use `underlying_asset`. There is **no** `base`, `underlying`, or `koinju_market_name` field — earlier docs had these wrong.

### Discovery examples — "What BTC products are available on koinju?"

```bash
# All BTC spot pairs (BTC as base OR quote)
curl -s 'https://api.koinju.io/market/spot' \
  | jq '[.[] | select(.base_asset == "BTC" or .quote_asset == "BTC")]'

# All BTC futures (perps + dated)
curl -s 'https://api.koinju.io/market/future' \
  | jq '[.[] | select(.underlying_asset == "BTC")]'

# Currently-listed BTC options
curl -s 'https://api.koinju.io/market/option/active' \
  | jq '[.[] | select(.underlying_asset == "BTC")]'

# Per-exchange count of BTC spot pairs
curl -s 'https://api.koinju.io/market/spot' \
  | jq -r '[.[] | select(.base_asset == "BTC")]
           | group_by(.exchange)
           | map({exchange: .[0].exchange, count: length})'
```

For a one-shot summary across all three market classes, pipe each into `jq 'length'` and sum.

### Python — `/ohlcv` example

Full parameter shape (including the `parseDateTime64BestEffort`-friendly date forms and the inverse-perp `-INV` suffix on `market`) lives in the autogenerated endpoint catalog at the bottom of this file.

```python
import os, requests

r = requests.get(
    "https://api.koinju.io/ohlcv",
    headers={"x-api-key": os.environ["KOINJU_API_KEY"]},
    params={
        "exchange": "binance",
        "market": "BTC-USDT",
        "candle_duration_in_minutes": 60,
        "start_datetime": "2026-05-13T00:00:00Z",
        "end_datetime":   "2026-05-20T00:00:00Z",
    },
    timeout=30,
)
r.raise_for_status()
candles = r.json()
```

## When to choose REST vs SQL

- **REST**: simple HTTP, no ClickHouse client needed, fine for small queries and dashboards.
- **SQL** (preferred for backtesting / research): joins, custom aggregations, window functions, push compute to the server. See `references/data-tables.md`.

#### `GET /funding-rate`
_Get funding rates for a perpetual market_
Funding-rate history for perpetual swaps across supported exchanges.

The settlement period is exchange-specific. Deribit publishes funding
hourly (continuous accrual); Binance, OKX, and Bybit publish discrete
funding events every 8 hours (sometimes 4h or 1h on select markets).
Consumers should infer the period from the gap between consecutive
timestamps for the same `(exchange, market)` pair.

Supported `exchange` values: `binance`, `bybit`, `okx`, `deribit`.
For cross-exchange queries, use the SQL API.

This endpoint is limited to 10000 records per request.
Auth: **`x-api-key` required**.

Parameters:

| Name | In | Required | Type | Description |
|---|---|---|---|---|
| `market` | query | yes | string | Koinju canonical perpetual symbol. Inverse perps carry the `-INV` suffix (e.g. `BTC-USD-PERP-INV` for the BTC-margined USD-quoted perp); linear perps don't (`BTC-USDT-PERP`). Use `/market/future` to enumerate available perpetual symbols. |
| `exchange` | query | yes | string (one of: binance, bybit, okx, deribit) | Exchange to filter by — one of `binance`, `bybit`, `okx`, `deribit`. For cross-exchange queries, use the SQL API. |
| `start_datetime` | query | yes | string | Window start. Accepts any format parseable by `parseDateTime64BestEffort` — e.g. a plain date (`2026-05-01`, treated as midnight UTC) or a full ISO 8601 timestamp (`2026-05-01T12:00:00Z`). |
| `end_datetime` | query | yes | string | Window end. Same format as `start_datetime`. Returned rows satisfy `start_datetime <= timestamp < end_datetime`. |
