# Framing the Question

## Standard

- **Osborn, _Applied Imagination_ (1953)**: generation on a vague problem scatters effort across unrelated solutions. <https://www.creativeeducationfoundation.org/>
- **Stanford d.school**: "How might we" turns a problem statement into an open, generative prompt that still carries the constraint of the underlying problem. <https://dschool.stanford.edu/>
- **Stanford d.school, _Design Thinking Bootleg_, "How might we"**: reframing as "how might we" invites many answers, where "how should we" invites one. <https://dschool.stanford.edu/resources/the-bootcamp-bootleg>
- A brief that names the decision, the decider, and the separating criterion is the only input that makes later passes checkable.

## Decision rules

1. If no one can name the decision the ideas serve, stop and get it; do not generate yet.
2. If the brief names a topic instead of a decision, reframe once before generating.
3. Split constraints into walls (fixed, cannot move) and fences (preferences, can move if the idea is strong enough).
4. If the decider is unnamed, the ideas have no audience; name them or run the session as practice only.
5. If two different decisions are packed into one brief, split them or run them sequentially.

## Procedure

1. Write the decision in one sentence: who will choose, between what options, by what criterion.
2. Name the decider, and name who else gets a say but not a vote.
3. Draft the brief in one paragraph: the context, the decision, the constraint.
4. List the constraints; mark each wall or fence; write one line of why for each wall.
5. Choose the scope: narrow (one feature), medium (one product area), wide (open field).
6. Reframe once: "How might we ..." for a generative angle, or "What would have to be true" for a constraint-probing angle.
7. Test the brief: would a stranger read it and produce ideas aimed at the same decision?

## Anti-patterns

- **Topic as brief.** "Ideas for the app" produces everything and nothing. Fix: name the decision.
- **Generating before the decider is known.** Ideas pile up with no test. Fix: name the decider first.
- **Walls and fences mixed.** A preference treated as a wall kills good ideas; a wall treated as a preference wastes time. Fix: mark each.
- **Framing twice, then again.** Endless reframing avoids generating. Fix: one reframe, then go.
- **Scope not stated.** The session drifts between feature, product, and company. Fix: pick a level.

## Done checklist

- [ ] The decision is one sentence with a decider and a criterion.
- [ ] The brief is one paragraph.
- [ ] Every constraint is marked wall or fence.
- [ ] The scope level is stated.
- [ ] One "how might we" or "what would have to be true" reframe is written.
