# DLMM position setup — pool, range, bins (1 Oct 2026)

Use when the user shows a **Create Position** form (meteora.ag) or asks "cara atur binnya udh bener lom?".
Screening picks *which pool* (`references/meteora-dlmm-lp-screening.md`); this file is *how to place the
ticket* — a separate decision, and the one where beginners lose money.

## Read the form first (5 values)

pool pair + **bin step** · Amount · Strategy · Min Price / Max Price · bin count.
Answer with numbers they can type, not theory.

## Bin mechanics (Meteora docs, Oct 2026)

- **Bins below the current price hold the QUOTE (SOL/USDC).** As price falls into them your quote
  converts to base → you are a *buyer*. Range entirely below spot = single-sided quote = **bid ladder**:
  earns nothing until price dips into it, then accumulates the falling token.
- **Bins above the current price hold the BASE token.** As price rises they convert to quote → *seller*.
  Single-sided base = sell ladder.
- Two-sided straddle (both tokens) earns from flow in both directions immediately.
- **Fees accrue only in bins that actually trade.** A wide range = most of the ticket idle = fee per
  dollar collapses while price exposure stays full. This is the #1 setup error.
- **Max 69 bins per position** (Meteora docs) — check the bin count, not just the prices.
- `bins = ln(max/min) / ln(1 + bin_step)`; bin step 50 = 0,5% per bin.

## The error to catch (worked example — e/acc, 1 Oct 2026)

User set Min $0,00887 / Max $0,0181 on a token at $0,017309 → 143 bins, **134 of them below spot**.
That is not a fee farm: ~94% of the money sits idle and the real trade is "buy e/acc all the way down to
−49%" on a token that was +138% in 24h. Fix handed over: ±3% (0,01679–0,01783, ~12 bins) or ±5%
(0,01644–0,01818, ~20 bins) around spot.

## Range width for a ≤24h fee trade

±3% to ±5% around spot. Narrow = all capital in the active bins (fees real) but out of range fast, then
you hold 100% of whichever side lost. Wide = resilient but idle. Name which trade-off they just bought.

## Strategy shapes (Meteora docs)

| Shape | Distribution | Use |
|---|---|---|
| Spot | uniform across the range | no view / range-bound; low maintenance |
| Curve | packed at the middle, near price | price stays put; highest fees while in range, fastest to leave it |
| Bid-Ask | packed at the edges, middle thin | volatility, DCA in/out, **single-sided** entries |

Narrow range → shape barely matters. Wide range → the shape *is* the thesis.

## Pool check before the ticket (do this first)

- Position must be **≤1–2% of pool TVL**. $300 into a $5,3k-TVL pool = 5,6% → you *are* the pool.
- Micro pools advertise absurd fee/TVL (that $5,3k pool showed **37,89%**, generated by ~$2k/day of
  arb-bot churn against the main pool). Same token's **SOL** pool: $291k TVL, 7,00% fee/TVL, ticket =
  0,10% → the correct venue. Quote both by address and re-check TVL live; the user frequently opens a
  pool the screen already rejected.
- Fee/TVL driven by a pump is not yield: check 1h/6h/24h change before recommending (e/acc was +138%/24h).

## Exit, stated as prices

TP +5% on position value · SL −8% on token price (entry × 0,92 — e/acc: 0,017309 → **0,0159**) ·
exit ≤24h regardless. Give the SL as a price they can set, never as "−8%".
