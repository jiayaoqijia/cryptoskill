# Idea Capture

## Standard

- **Cohn, user stories**: the "As a [who] I want [what] so that [why]" form forces an idea to name its beneficiary and its purpose, not just its feature. <https://www.mountaingoatsoftware.com/agile/user-stories>
- **Ries, _The Lean Startup_ (2011)**: every idea rests on a leap-of-faith assumption; the smallest test that can falsify it is the next step, not the full build. <http://theleanstartup.com/>
- Wording stability: an idea that is reworded each session cannot be tracked or compared.

## Decision rules

1. If an idea cannot fit one line with a "so that" clause, it is still a cluster, not an idea; split it.
2. Two ideas whose one-line and assumption match are one idea; merge and keep the earlier wording.
3. Capture records the idea, not the design; stop at the line, the assumption, and the test.
4. If the cheapest test is missing, the idea is only noted, not captured.
5. Wording is frozen once captured; edits are new versions, not silent rewrites.

## Procedure

1. Take each surviving idea from the shortlist.
2. Write one line: the idea in plain words.
3. Add the "so that" clause: who benefits, and why.
4. Name the assumption the idea rests on: "this works only if ...".
5. Name the cheapest test that would falsify the assumption.
6. Merge duplicates: same line and same assumption become one entry; keep the first wording.
7. Write the entry once and reuse it verbatim in later sessions.

## Anti-patterns

- **Vague phrase.** "Improve onboarding" captures nothing. Fix: one line plus a so-that clause.
- **Capture as design.** The entry grows into a spec. Fix: stop at line, assumption, and test.
- **Silent rewording.** The idea changes wording each meeting and nobody can tell. Fix: freeze wording; version new edits.
- **Duplicate proliferation.** Ten phrasings of one idea survive. Fix: merge on line plus assumption.
- **Test missing.** "We should do X" with no way to check it. Fix: name the cheapest falsifier.

## Done checklist

- [ ] Each idea is one line with a "so that" clause.
- [ ] Each idea names its assumption.
- [ ] Each idea names its cheapest test.
- [ ] Duplicates are merged to one entry.
- [ ] Wording is stable and reusable verbatim.
