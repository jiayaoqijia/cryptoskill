# Evaluation Scenarios

Test specifications; independent runs are not claimed.

- Revise a systems-security draft for USENIX with marketing claims ("completely prevents... with negligible overhead"): produce quantified rewrites with measured bounds and populations.
- Draft with no threat model or a model that drifts between design and evaluation: produce an early precise threat model and an adversary-consistency check across every evaluation claim.
- Page-budget pass on an over-length draft: report per-section usage against the current USENIX budget and route overflow to appendices without template or spacing tricks.
- Disclosure narrative check: a scan paper or vulnerability report must carry rate limits, opt-out handling, and vendor-report timing at the point of need.
- Cold-reader framing check: read intro + threat model only, state the claimed contribution, and compare with the paper's actual claims.
- Page limit or template may have changed: verify the current USENIX call and record a dated snapshot rather than asserting remembered rules.

Score threat-model precision, quantified calibration, disclosure completeness, page-budget discipline, and absence of fabricated content.
