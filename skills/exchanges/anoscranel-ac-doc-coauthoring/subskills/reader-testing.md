# Reader Testing

## Standard

Stage 3 executes the fresh-reader test as the final quality gate before document release. Grounded in US federal plain-language standards and ISO 24495-1 principles, this review requires evaluating the completed text from the perspective of an intelligent reader possessing zero background context from the co-authoring session. The test specifically audits for unglossed technical jargon, unstated premises, missing rationale, and logical leaps where the text raises questions and leaves them hanging. The standard mandates running this simulation cleanly, cataloging discovered comprehension gaps, and making targeted revisions before final publication.

## Decision rules

1. Simulate a naive reader persona who has no prior participation in the co-authoring session or internal context.
2. Flag any technical term, acronym, or concept introduced without an immediate gloss or definition.
3. Identify hidden assumptions where the author knows the background but the text fails to state the premise.
4. Check every major claim for supporting evidence or clear rationale, marking unsupported assertions for revision.
5. Limit post-test edits to clarity, structure, and missing context adjustments without reopening core scope debates.

## Procedure

1. Read the finalized document end-to-end adopting the perspective of an informed outsider encountering the text cold.
2. Record every instance of confusion, ambiguous transition, unexplained jargon, or unaddressed reader objection.
3. Compile the findings into a concise reader-friction report categorizing issues by severity (minor phrasing vs core gap).
4. Present the report to the author with specific remediation suggestions for each identified friction point.
5. Apply approved edits to resolve comprehension gaps, securing the final text quality before session closing.

## Anti-patterns

- Skipping the fresh-reader test because the author and co-author both understand what was intended.
- Conducting the test with insider bias, forgiving unclear phrasing because the context is already familiar.
- Overwriting the entire document based on subjective style preferences rather than verified comprehension friction.
- Ignoring flags about unexplained jargon or missing rationale.

## Done checklist

- [ ] Fresh-reader simulation executed across the entire completed draft.
- [ ] Jargon, hidden assumptions, and unsupported claims cataloged.
- [ ] Reader-friction report presented and reviewed with the author.
- [ ] Targeted clarity revisions applied to resolve all identified comprehension gaps.
