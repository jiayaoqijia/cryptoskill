# Taste Development

## Standard

- **Deliberate practice**: targeted reps with feedback, not passive exposure (Ericsson et al. 1993, https://doi.org/10.1037/0033-295X.100.3.363).
- **NN/g heuristic method**: critique is a learnable protocol, not a gift (https://www.nngroup.com/articles/how-to-conduct-a-heuristic-evaluation/).
- **Dieter Rams, "Good design"**: a named canon to argue against (https://www.vitsoe.com/us/about/good-design).
- **Constraint drills, swipe files, and canon audits**: ⚠️ practitioner convention, no single canonical source.

## Decision rules

1. Reps beat reading. One written teardown a week beats ten articles.
2. If you cannot say why a design is good, it is not in your canon yet.
3. If hierarchy must be trained, work under constraint: one color, one size, spacing only.
4. Critique shipped UIs, not hero shots on galleries.
5. If a judgment is unwritten, it does not compound. Score it.
6. If you review alone forever, taste drifts toward preference. Outside review monthly.
7. If reps feel easy, raise the difficulty: denser screens, worse inputs, time caps.

## Procedure

1. Keep a swipe file: a screenshot plus a two-line note on why it works.
2. Run one weekly teardown: a shipped screen, the full critique protocol, rubric scores.
3. Compare your notes with a public review or a peer's notes. Log disagreements with reasons.
4. Run a monthly constraint drill: redesign one screen under a hard constraint (grayscale only, one family, 90 minutes).
5. Share one critique per month for outside review.
6. Audit the canon quarterly: keep or cut entries; every entry carries a written reason.
7. Re-score your reference set quarterly. Track the drift of your own numbers.

## Anti-patterns

- Saving without annotating. Fix: every save gets a written why.
- Studying only polished marketing pages. Fix: critique working UIs.
- Mimicking the in-house style. Fix: written reasons first.
- No feedback loop. Fix: monthly outside review.
- Never re-testing old judgments. Fix: re-score the reference set quarterly.
- Collecting canons by volume. Fix: cut more than you keep.

## Done checklist

- [ ] Every swipe-file entry carries a note.
- [ ] Four weekly teardowns this month.
- [ ] One constraint drill this month.
- [ ] One externally reviewed critique this month.
- [ ] Canon entries have written reasons.
- [ ] Reference set re-scored this quarter.

Development is comparative rather than absolute: the useful exercise is to place two artefacts side by side and say which is better and why, because the reason is the taste and the preference is only its symptom. A practice that collects preferences without reasons collects nothing.
