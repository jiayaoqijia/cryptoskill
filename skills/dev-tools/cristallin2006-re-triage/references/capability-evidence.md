# 能力识别：组合特征、作用域与未命中

用于未知样本的能力候选和下一步取证选择。capa 规则描述“哪些特征在什么作用域内共同出现”；可借鉴其表达方式进行人工分析，不把规则库目录当成必须执行的检查清单。

## 从单点命中走到可解释候选

1. 保留样本 hash、架构、代码地址和提取来源。先确认特征来自当前代码，而非未使用的数据、链接库或错误反汇编。
2. 查组合关系：AND/OR、计数、同一指令/基本块/函数作用域、对子规则的引用。跨函数拼出的 API 名单不能代替“同函数”的规则条件。
3. 用候选指导取证。例如 selector 0x33 单独出现不足以认定 Heaven's Gate；还需核对相关指令、远返回与实际处理器模式。匹配组合也仍需检查可达性和环境。
4. 记录反例：正常程序、调试器或安装器可能具有相同能力。能力存在不等于恶意意图，不等于漏洞，更不等于可利用。

## 规则与引擎的边界

- 规则的 static/dynamic 支持和作用域是实际约束。所读 Heaven's Gate 规则标注 static=function、dynamic=unsupported；动态记录里没有它所需的特征不能记为“检测通过”。
- 未命中可能源于壳、未提取代码、缺失特征、架构或规则覆盖；不能由“没有规则命中”推出“无此能力”。nursery 规则还需留意其成熟度。
- 若实际执行 capa，记录引擎版本、规则 commit、后端、样本和匹配地址。引擎不可用时只交付人工核对的候选，不伪造规则执行结果。

本卡只负责分诊与证据组织。函数语义继续交 ghidra-static，运行时行为交 re-dynamic，缺陷和影响交 vuln-audit；不因标签命中自动启动网络操作或重写样本。
