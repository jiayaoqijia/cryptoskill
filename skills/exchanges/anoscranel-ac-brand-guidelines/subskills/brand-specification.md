# Brand Specification

## Standard

- **GOV.UK Design System Style Guide**: public sector standards for consistent voice, tone, and terminology across publishing channels. <https://www.gov.uk/guidance/style-guide>
- **Microsoft Writing Style Guide**: public enterprise reference for clear, inclusive voice attributes, preferred terminology, and formatting rules. <https://learn.microsoft.com/en-us/style-guide/>
- **ISO 24495-1 Plain Language Principles**: international standard requiring clear, relevant, and usable communication design. <https://www.iso.org/standard/78907.html>
- **AP Stylebook Principles**: authoritative guidance on consistency, spelling, and directness in professional writing. <https://www.apstylebook.com/>
- ⚠️ House convention: a brand specification is an unnegotiable single source of truth; any published text contradicting its terminology or voice attributes is classified as a brand defect.

## Decision rules

1. Define the core mission in exactly one sentence before listing any voice attributes or terminology rules.
2. Every voice attribute must be paired with concrete do-say and don't-say examples to eliminate subjective interpretation.
3. Establish a clear tone-by-channel matrix separating documentation, marketing, and support communications.
4. Maintain an explicit terminology list designating mandatory preferred terms and strictly banned terms.

## Procedure

1. Gather core company mission statements, customer research insights, and existing publication samples.
2. Draft the mission statement and define primary and secondary audience segments.
3. Select three to four core voice attributes (for example: direct, precise, calm, helpful).
4. For each voice attribute, write at least two do-say examples and two don't-say examples.
5. Build the tone-by-channel matrix defining appropriate registers for technical docs, marketing announcements, and support replies.
6. Compile the terminology dictionary listing preferred replacements for common jargon or legacy product names.
7. Publish the complete specification as a locked reference document for all subsequent audits and content creation.

## Anti-patterns

- Listing abstract voice attributes like "innovative" or "world-class" without defining do-say examples.
- Creating conflicting tone requirements where technical documentation adopts playful marketing slang.
- Omitting banned terms, leaving writers free to use legacy or deprecated product terminology.
- Treating the brand specification as an optional suggestion rather than a binding compliance standard.

## Done checklist

- [ ] Mission statement is captured in a single sentence.
- [ ] Primary and secondary audiences are explicitly defined.
- [ ] Three or more voice attributes are documented with concrete do-say and don't-say pairs.
- [ ] Tone-by-channel matrix covers documentation, marketing, and support channels.
- [ ] Terminology list specifies preferred and banned terms.
- [ ] Formatting and capitalization rules are clearly articulated.
- [ ] Document is formatted as a single reference standard.
