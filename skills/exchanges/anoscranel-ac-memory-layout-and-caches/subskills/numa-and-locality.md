# NUMA and locality

## Standard

On a multi-socket machine, each socket has local memory that is fast to reach and remote memory that crosses an interconnect, and the difference is a substantial fraction of DRAM latency. A thread's allocations start local under default policy, but a thread that migrates between cores on different sockets inherits remote access to its own working set: the data did not move, the thread did.

The design decisions are affinity and placement. Pinning a thread and its memory to one node makes the access pattern local and stable; allowing free migration can balance CPU load while quietly converting every access to a remote one. Neither choice is free, and the honest approach is to measure the remote-access fraction — a counter most kernels expose per process — before pinning anything.

Primary sources: <https://www.akkadia.org/drepper/cpumemory.pdf> and <https://www.brendangregg.com/linuxperf.html>.

## Decision rules

- Record the topology: node count, which cores belong to which node, and interconnect.
- Measure the remote-access fraction before choosing a pinning policy.
- Record the allocation policy for large regions: local, interleaved, or explicit.
- Prefer interleaved allocation when the access pattern is inherently shared across nodes.
- Record any thread-affinity setting and the scheduler's ability to override it.
- Re-measure remote fraction after the policy change, not only end-to-end time.

## Procedure

1. Map the node topology and core-to-node assignment.
2. Measure remote-access fraction per process or thread group.
3. Identify large regions and their allocation policy.
4. Choose local for node-private data, interleaved for truly shared.
5. Apply affinity where measurement shows migration loss.
6. Re-measure and record both the fraction and end-to-end time.

## Anti-patterns

- Pinning threads without measuring the remote fraction first.
- Interleaving all memory by default.
- Ignoring thread migration as the cause of remote spikes.
- Assuming a two-socket policy transfers to four sockets.
- Judging by end-to-end time without the remote fraction counter.

## Done checklist

- [ ] Topology recorded.
- [ ] Remote fraction measured.
- [ ] Large-region policies recorded.
- [ ] Local vs. interleaved chosen per region.
- [ ] Affinity applied where justified.
- [ ] Both counters re-measured.

The interconnect also carries traffic for coherence, so remote access and cache-line transfer compete for the same wires: a workload that is local everywhere can still saturate an interconnect through false sharing at distance, and the remote-access counter will under-report it because the traffic is generated by invalidations rather than by loads. Two counters, not one, decide the placement question.
