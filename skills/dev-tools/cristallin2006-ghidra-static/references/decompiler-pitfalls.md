# 反编译伪码：疑点、证据与分析状态

用于结论依赖反编译语义且存在疑点的区域。伪码可用于导航、生成假设和支持局部解释；是否需要交叉验证取决于结论及疑点，不要求每题全量反编译、固定工具顺序或逐次台账。

## 1. 对照视图的能力与边界

| 视图 | 可提供的证据 | 注意事项 |
|---|---|---|
| 原始字节 | 实际文件/内存中的常量、指令编码与长度 | 注明文件偏移/虚拟地址、映像或运行时版本；bss/重定位后数据不一定在文件中 |
| 反汇编 | 跳转、访存、位运算、字段位置 | 依赖架构/模式与代码边界，数据也可能被误解成指令 |
| P-code | 显式位宽、截断、扩展和语义关系 | 高低层 P-code 与分析状态有关，不视为完全没有类型/控制流推断 |
| 伪码 | 结构化表达、类型假设、局部数据流与导航 | 可能折叠路径、误定类型或遗漏间接控制流；告警提示复查范围 |

这些视图没有适用于全部问题的绝对权威排序。结论依赖某处常量、路径或宽度时，选择能区分解释的相关证据，保留地址和来源。静态证据充分时可以交付限定结论，缺运行后端不自动阻止分析。

Ghidra 项目有状态：反汇编/建函数、`disassemble --force`、跳转表恢复、类型与 NoReturn 修正可能持久改变后续视图。对照实验记录干预及原始状态；先前修过的区域不能充当“未经处理”的基线。需要独立对照时使用明确保存的旧版本或独立项目，不擅自覆盖共享项目。

## 2. 典型疑点与可选核查

| 现象 | 可能解释 | 可选核查与边界 |
|---|---|---|
| jumptable 告警、间接 JMP 被渲染成 CALL | 控制流未恢复或尾调用 | 查看相关指令及分发器；尾声附近 JMP 是尾调用线索，不由单一模式定案 |
| 只看到部分跳转表 | 其他基址、路径或间接计算遗漏 | 依据索引和消费者查相关基址；明确实际覆盖，未证明只有一张时不声称完整 |
| 同名栈槽出现不同宽度/角色 | 生命周期复用、重叠对象或错误类型 | `frame_map.py`、访存宽度、前后定义；变量名不足以证明同一对象 |
| `&DAT_...`、整数字面量或偏移可疑 | 指针化渲染、类型错误或真实的指针值 | `read_views.py`、`const_audit.py` 对照相关指令/字节；真实 LEA 指向字符串中部不必是漂移 |
| `auVar`/`CONCAT`/`SUB`、向量化比较 | 向量化或位域表达 | 恢复具体宽度/掩码；可提出 memcmp 等等价模型，但需核对关系 |
| CALL 后路径消失、大量灰色、NoReturn 传播 | 真实终止、异常路径或误标 | 查看终止指令与调用约定；UD2/INT3 可由 signal/exception handler 改写保存状态，不直接判不可达 |
| 同类型值二选一但条件不明 | 轮次/模式分支、等价计算或生成噪声 | 查看条件的数据依赖，或有权限时做单因素对照；不凭外观忽略分支 |
| 生成代码反复使用同一变量名 | Cython/优化代码的临时槽复用 | 类型元数据、定义使用链和相关行为；有调试符号时也核对其适用版本 |
| 多次递归或大量相似调用看起来不合理 | 忠实代码或恢复错误均可能 | 查看实际 CALL/边，不能因为“看起来怪”就归咎反编译器 |

历史单一样本曾把 468 个函数中 28 个告警函数计为 6.0%；对其中 15 个尾调用误报复核后，待检查口径变为 13/468（约 2.8%）。这只说明该样本的统计与工具启发式需要校准，不是其他程序的错误率或“低于此比例即可靠”的阈值。

## 3. 按问题选择路径

- 单点结论：定位相关函数/比较点，读必要视图；不必先运行 `decompile-all`。
- 大范围伪码已经可用：`decomp_lint.py` 可列待核对告警；其 `fatal` 标签不是禁止阅读，也不是目标错误证明。
- 类型噪声阻碍理解：可修签名、调用约定或结构类型后重反编译，记录干预；不要以类型修正后的结果证明原始视图无问题。
- 跳转表未恢复：`jt_resolve.py` 可生成候选目标。CFG 检查需要相关目标已被正确识别；未反汇编时可在获准项目中恢复，或先使用索引范围与目标字节等证据。不能把替代检查冒充已完成 CFG 验证。
- NoReturn/异常路径疑点：`noreturn_fix.py` 可定位或修正分析标记。修改前核对依据和项目归属，修复后的路径仍需说明实际条件。
- 需要行为证据：依可用后端选择函数仿真、整程序模型或真实执行。桩、ABI、初始状态和输入通道可能造成差异；打补丁后的成功不等于原始目标接受。
- 依赖结构简单：可分析调用/数据依赖再做局部反推；SMT、剥离和枚举按结构与成本选择，没有普遍的固定升级阶梯。

格式诊断见 `crypto_sanity.py --help`：Base64 要区分字母表和 padding 契约；不可打印候选可能是合法二进制。诊断不通过只说明所检查条件未满足，既不能直接归因读数错误，也不能证明目标不可解。

## 4. 交付与复查

写明支持结论的相关地址/字节、输入、模型范围与未排除解释。工具一致或脚本往返只支持相应路径；采用、归因、更正与撤回都说明证据，不为“我改正了”免除核对。

阶段性负结果保留实际测试条件；不重复同条件实验来制造进展。需要新证据时选择有区分力的实验；继续有价值的静态推理也是合理选择。会话与复核使用当前 analysis-session/analysis-memory 接口，不恢复旧版回访 delta 等机械门。

## 5. 配套脚本

| ghidra-core/scripts/ | 用途 |
|---|---|
| `decomp_lint.py` | 已有伪码的告警与渲染疑点清单 |
| `call_histogram.py` | 调用目标分布，帮助定位重复模式 |
| `read_views.py` | 相关字节的多种表示和显式长度/内容对照 |
| `jt_resolve.py` | 支持模式下的跳转表基址与候选目标 |
| `frame_map.py` | 栈槽使用和宽度线索 |
| `const_audit.py` | 常量渲染疑点，结果仍需结合上下文 |
| `noreturn_fix.py` | NoReturn/终止路径诊断与获准的分析修正 |

素材来自历史本地复盘；案例统计与路径仅作为来源背景，不要求访问或安装原机器目录。通用输入与证据约定见 [核心证据卡](core-evidence.md)。
