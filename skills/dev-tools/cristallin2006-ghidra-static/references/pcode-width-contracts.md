# 用 P-code 核对位宽与有符号语义

伪码中有截断、溢出、类型提升、移位或条件比较疑点时读取。直接从与问题相关的指令/P-code 核对即可，不要求每次分析都走固定的反编译流水线。

| 线索 | 核对要点 |
|---|---|
| INT_ADD/INT_SUB | 输入和输出宽度；按该位宽取模，进位/有符号溢出由其他操作表达 |
| INT_ZEXT / INT_SEXT | 先确定源宽度，再决定补零或扩展符号位；0x80 从 8 位扩到 16 位分别得到 0x0080 / 0xff80 |
| INT_LESS / INT_SLESS | 相同字节序列按无符号/有符号解释可能相反；输出是布尔值 |
| 移位与掩码 | 使用的 P-code 操作、操作数位宽及生成的计数掩码；不要把 Python 整数或 C 表达式的默认行为直接套入 |
| LOAD/STORE 与拼接/切片 | 地址空间、大小、字节序及实际使用的字节；伪码中的变量名不决定真实存储边界 |

保留地址、原字节、语言/处理器配置和相关 P-code。raw P-code 与反编译器变换后的表示并非每条一一对应；存在翻译、指令模式或反编译假设疑点时进一步核对反汇编及实际执行，不把 IR 自动视为独立运行证据。

局部表达式明确后可使用 SMT 比较候选实现；完整建模所有相关初始条件。Python 中 `0xff + 1 = 256` 不能代替 8 位运算，8 位结果应为 0；C 有符号溢出的语言规则也不能直接替代机器指令语义。

本卡负责语义约束；Ghidra 的 RPC、数据库事务和视图导出仍由 ghidra-core 提供。动态实验按需交 re-dynamic，不自动迁移专业任务，也不增加全局质量门禁。
