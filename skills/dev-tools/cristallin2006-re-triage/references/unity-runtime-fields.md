# Unity/Mono 运行态字段路线

仅在样本确认为 Unity + Mono 程序集时启用；普通 .NET、IL2CPP 和 NativeAOT 各走原路由。

1. 先列 `*_Data/Managed` 内所有程序集及其哈希，确认 `Assembly-CSharp.dll` 以外的游戏 DLL、热更新 DLL、资源配置和加载顺序。只从第一个 DLL 得到可读明文，不代表它是最终校验值。
2. 从输入控件、校验函数与成功 UI 反向追字段：标明 `static`、实例、构造时赋值、资源反序列化赋值及运行时覆盖。搜索赋值点和引用点，记录对象实例与调用时刻。加密材料应分别记作密文、key、IV、来源程序集/字段。
3. 对候选用原游戏未修改进程做正反例：同一入口输入候选和一字节变体，记录 UI 原文、窗口/进程、样本哈希与环境。静态离线解密只能证明公式能产出字符串；原游戏拒绝时，回查第二密文、实例字段与执行分支，不能直接归因为 flag 包裹格式。
4. 运行态观察可用 dnSpyEx 断点或 Mono 字段读取。若 Wine 与 Windows 结果不同，记录最小输入差分并在隔离的 Windows 环境复验。补丁只用于找分支，验收必须回到未修改游戏。

输出：程序集清单、字段赋值链、正负例回执，以及仍待排除的候选来源。不要把某题的密钥或字节常量写成通用规则。
