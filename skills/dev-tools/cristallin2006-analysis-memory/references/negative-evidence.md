# 关键负结果与重复实验

在准备重复实验、放弃重要路线或交接失败结论时使用。复用已有 source、experiment、claim 与 query；不另建失败台账，不要求普通工具操作逐条填表。

一项有价值的负结果应限定：测试了什么命题、目标代次、入口与会话条件、输入或生成规则、工具/环境及干预、原始输出、实际执行状态。experiment.details 已有 excludes 和 does_not_exclude；仅排除本次证据覆盖的范围。超时、缺依赖、无法判别响应不能记作技术假设已被否定。

检索时从目标/代次、服务入口、命题和关键输入找相关记录，再展开原来源。必要时换关键词并检查 scan_truncated；无命中不代表此前未尝试，近似文本也不保证实验等价。

相同条件的有效负结果通常可以复用。复试可基于新材料、目标/会话或工具条件变化、旧实验的覆盖缺陷、稳定性验证或正负对照；说明变化即可，不逐请求重复写理由。只换 worker、脚本文件名或字典文件名不增加证据，也不重置预算。

有冲突先核对条件和版本；同条件反证保留双方，不覆盖原始失败记录。重要负面结论应注明下一项区分实验或合理暂缓原因；“暂时不值得继续”不能写成“已经证明不可解”。

跨分支共享有来源、有适用范围的线索；目标变化后复核旧结论。凭据不进入普通记忆或快照，不因为相似题名、平台或网段就向所有 worker 广播或扩展授权。

checkpoint 记录阶段信息，不自动生成 memory 对象；context 为空不证明没做过实验。重要误判被新证据推翻时，按当前修订 revise/link supersedes 或 invalidate，保留原来源及实际反证；只在 NOTES 末尾补一句不会自动使旧派生方法失效。值不值得形成候选由当前任务判断，不强制每次推导都发布。“不可解”需覆盖依据，未排除解释可给区分实验或合理暂缓原因，不要求缺后端时仍强行做实验。
