# NES 状态分析

只对 iNES ROM 生效。先用成熟且带 CPU/RAM 调试器的模拟器载入 ROM，保存同一基线状态；自行编写 PPU/整机模拟器属于最后的专门需求。

1. 从胜利画面字符串、绘图写入或终止分支反向找状态读点；在可疑 RAM 地址下读/写断点，找谁更新、何时比较、比较门槛。按帧记录 PC、关卡/计数器和目标状态。
2. 实验前保存状态。每次只改一个 RAM 地址，其余输入、帧数和随机状态固定；从同一存档做未改、目标值、相邻值三个对照。步进足够帧让主循环执行状态检查与渲染，保存截图和 RAM 差分。只跑三帧后未见画面不能判“未通关”。
3. 若写目标状态后显示胜利，结论是“该状态可触发胜利画面”；还需从写点/输入路径证明合法通关条件。不要全 RAM 赋常数后用偶然画面推断规则。
4. 将 ROM 哈希、模拟器版本、基线存档、地址及读写点、帧数、截图路径落台账。模拟器观察和原 ROM 正常输入路径应明确区分。

Flare-On `snake.nes` 的 `$25/$26/$27` 属个案验收数据，不是其他 ROM 的通用地址。
