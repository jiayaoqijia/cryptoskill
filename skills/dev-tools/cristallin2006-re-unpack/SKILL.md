# re-unpack

## 输入与输出

输入为原样本、包装线索、架构与执行条件；输出为原始/产物 hash、提取步骤、基址/OEP、完整性检查和限制。

按包装类型选择官方解包工具、仿真、动态 dump 或 Ghidra stub 分析；高熵/壳节名先复核误报。保留原样本，解包写新文件。压缩数据可分析格式、头、边界与恢复条件，不把所有 packed 字节一律当无信息。

验证格式、节/段、入口、必要导入与重定位，以及原目标所需行为；未完整恢复的 dump 可作局部证据，清楚说明限制。PyInstaller/pyc 按 magic/版本选反编译器，必要时用字节码视图。PE 内存镜像交接保存 OEP/基址，Ghidra import-raw 用匹配处理器。

不同工具层次按当前失败原因选择；不强制逐级时间盒或全部尝试。工具发现与 rootfs 配置来自运行环境，缺后端时报告可分析部分和下一步。

## 会话与交接

按当前问题选方法，可静态先行、动态先行或直接建模。连续实验没有新增证据时盘点前提和可区分解释的实验；时间盒用于复查，可说明价值后继续原路线。

简单单点查询记录最小证据即可；多阶段、恢复或协作任务按需使用 analysis-session，记录关键结论、目标代次、实验干预和未决问题。普通工具事件由运行层记录。候选与外部接受分别说明，可交付限定范围的未完成报告。共享项目写操作协调所有权；未获变更权时先只读。
