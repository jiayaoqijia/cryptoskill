# Unity/Mono 场景探索路线

适用条件：`re-triage/SKILL.md` 的 Unity 子路由已确认目标主要是到达或观察场景。输入校验题继续走 `unity-runtime-fields.md`；普通 .NET、IL2CPP/NativeAOT 及其他题型不读本页。

## 从线索到可观察位置

1. 列出 Build Settings 中的场景顺序、入口场景和场景文件大小；标出明显离群项，但大小仅决定优先级，不证明答案位置。汇总游戏内可见文字、坐标、方向提示和相关 Player/Camera/Scene/Death 代码，形成“线索 → 场景 → 位置/视点 → 下一次实验”表。先查有指向的场景，不盲扫全部场景。
2. 坐标可能是角色位置、附近观察点、目标物位置或触发点。精确坐标没有独立 GameObject 时，检查附近几何、文字、朝向、高度与遮挡；不能把一次对象搜索的空结果扩大成“该处无内容”。静态字符串搜索未找到 flag 也只证明所搜字节范围没有明文。
3. 先运行未修改游戏，确认入口场景、正常移动、相机操作、死亡/加载行为。若路径被能力或关卡门槛阻断，在游戏副本上按需做最小探索补丁：跳跃/移动、传送、场景切换、死亡区域或相机限制。记录原始与补丁 SHA-256、补丁差异和回滚方法。补丁是找位置的实验，不是原游戏或平台接受答案的证明。

## 运行时到达与视点取证

- 修改 `CharacterController` 角色的 `transform.position` 前，先停用该控制器，设置位置后恢复，再从运行中的对象回读坐标。仅改场景序列化初始位置或截一张图，不算证明运行时到了目标。
- 使用 `SceneManager.LoadSceneAsync` 等切场景方法时，等待加载完成，记录加载后的场景名/索引和角色位置；“原代码没有切场景调用”不等于其他场景不可探索。
- 同一目标至少记录场景、角色坐标、相机位置与朝向、时间/操作、原始截图；难读字符再留局部放大与第二视角或资源几何复核。看不到图案时，先变换视角、距离、高度和朝向，检查遮挡、背面、洞口、水下及近距离相机限制，再更新假设。
- Windows 专属 GUI/Unity 行为优先在隔离的 Windows 原生环境观察；Wine 与原平台矛盾时以原平台复验。记录环境与游戏副本版本，避免混合不同运行条件的截图。

## 碎片、候选与否定结论

每段视觉碎片记录来源场景、位姿、截图、转写和不确定字符；按提示建立顺序，不凭 flag 格式猜缺字。多段拼接只记为候选。`ledger.py --kind finding` 可记录视觉证据；仅在未修改原程序或平台真实接受时才用 `--kind flag`，无游戏输入入口时可使用现有 `--accept-scope platform` 与题目 ID 回执。平台不可用就标“候选未验证”。

以下观察只支持局部结论：明文扫描为空、某坐标无独立对象、当前视角空白、当前场景无加载调用。若要作“没有视觉碎片/其他场景不可达”等全局否定，必须列明已覆盖的场景和视点、运行时位置、遮挡/死亡边界、资源几何及每条未排除路线；缺关键维度时记 `unknown`，写出下一次实验。不得用 `static-constraint:` 前缀包装单次空搜索，并让它锁死后续探索。

交付物：场景/线索表、可复现的运行时操作、每段碎片的截图与位姿、补丁清单、拼接依据，以及原程序或平台的验收状态。不把具体题目的坐标、场景名或 flag 片段写成通用规则。
